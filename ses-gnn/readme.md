## Запуск

```bash
# 1. SES поверхность
python preprocess.py --dataset training_ppi.txt --pdb_dir ./pdb_files --out_dir ./data/raw

# 2a. Однородные графы (R=3 Å)
python build_graphs.py --no_multiscale --r_cutoff 3.0 \
    --raw_dir ./data/raw --out_dir ./data/graphs_uniform

# 2b. Мультимасштабные графы v2 (рекомендуется, полные рёбра)
python build_graphs.py \
    --raw_dir ./data/raw --out_dir ./data/graphs_multiscale \
    --r_local 2.0 --r_mid 4.0 --r_global 8.0 \
    --k_mid 10 --k_global 10 --sigma 3.0 \
    --max_neighbors 1000

# 3. Топологическая глубина (опционально — для WBCE-depth)
python compute_geodesic_depth.py \
    --data_dir ./data/graphs_multiscale \
    --out_dir ./data/graphs_multiscale_depth \
    --threshold 4.0 --local_r 2.0

# 4. Обучение (финальная конфигурация — 8 слоёв, WBCE α=0.5)
python train_clean_ddp.py \
    --data_dir ./data/graphs_multiscale \
    --log_dir ./logs/final_wbce_a05 \
    --n_files 5000 --n_val 50 \
    --layers 8 --hidden 32 --heads 4 \
    --hard_ratio 2.0 --bias_init -0.85 \
    --weight_alpha 0.5 --weight_tau 4.0 \
    --weight_mode y \
    --epochs 100 --val_interval 2

# 5. Оценка на test
python evaluate.py \
    --model ./logs/final_wbce_a05/best_roc.pt \
    --data_dir ./data/graphs_multiscale \
    --output_dir ./eval_final_wbce \
    --n_files 412 --shuffle_seed 42 --train_val_size 5050 \
    --layers 8 --hidden 32 --heads 4

# 6. Визуализация
CUDA_VISIBLE_DEVICES='' python viz.py \
    --model ./logs/final_wbce_a05/best_roc.pt \
    --name 2VT3_B_A \
    --pt_dir ./data/graphs_multiscale \
    --auto_threshold --edge_scale \
    --save ./viz_out/2VT3_final.html
```

## 🧬 Мультимасштабные графы: алгоритм построения

Вместо одного радиуса (3 Å) мы строим рёбра на трёх масштабах:

1. **Локальный (0–2 Å)**: все рёбра между точками. Мелкая геометрия.
2. **Средний (2–4 Å)**: до 10 центроидов через Farthest Point Sampling (FPS). Контекст размера остатка.
3. **Глобальный (4–8 Å)**: до 10 центроидов через FPS. Форма сайта в целом.

Все рёбра объединяются в один граф, для каждого ребра вычисляются признаки: расстояние, косинус угла между нормалями и экспоненциальный вес (σ=3.0).

### Версия 2: полные рёбра (без неявной обрезки)

**Проблема v1.** В исходном `build_graphs.py` использовался `torch_cluster.radius_graph` со стандартным `max_num_neighbors=32`. Это неявно обрезало рёбра **до** FPS: локальные рёбра (0–2 Å) занимали почти весь бюджет, и на средний и глобальный масштабы оставалось ~12 кандидатов вместо сотен. Результат: FPS выбирал центроиды из близких точек, а не из полной окрестности; глобальный масштаб фактически не работал.

**Решение v2.** Параметр `--max_neighbors` (default = 1000) снимает неявную обрезку. Кандидаты в каждом масштабе — полные:

| Масштаб | Кандидатов до FPS | После FPS |
|:---|:---|:---|
| Локальный (0–2 Å) | 19.9 | 19.9 (без FPS) |
| Средний (2–4 Å) | 76.8 | 10 |
| Глобальный (4–8 Å) | 373.6 | 10 |
| **Итого** | — | **~40 рёбер/вершину** |

Для сравнения, v1 давала **27 рёбер/вершину**, из них лишь ~2 глобальных.

**Статистика** (по 20 белкам датасета, `analyze_graph_degrees.py`):

```
── ПОСЛЕ FPS ──
  Всего degree:           39.9 ± 0.2  (max 60)
  Локальный (0–2 Å):      19.9 ± 0.2
  Средний   (2–4 Å):      10.0 ± 0.0
  Глобальный(4–8 Å):      10.0 ± 0.0

── ДО FPS (кандидаты) ──
  Средний   (2–4 Å):      76.8 ± 2.1
  Глобальный(4–8 Å):     373.6 ± 18.7
```

**Совместимость.** Формат `.pt` сохранён, v2-графы подключаются тем же `train_clean_ddp.py`. Но метрики v1 и v2 **не переносятся** — состав рёбер отличается.

**Проблема со сплитом.** При пересборке один файл (`2AVU_E_F.pt`) не собрался из-за ошибки → 5461 вместо 5462. `random.Random(42).shuffle` на разной длине даёт разные перестановки, поэтому train и val **не совпадали** с v1. После восстановления файла сплит совпал.

### 📈 Сравнение v1 vs v2 мультимасштабных графов

| Модель | Графы | Слоёв | Test ROC | Test PR | Test F1 (opt) |
|:---|:---|:---|:---|:---|:---|
| **12L v1** | 27 рёбер, обрезка 32 | 12 | 0.838 | 0.622 | 0.612 |
| **8L v2** | **40 рёбер, без обрезки** | **8** | **0.8435** | **0.6430** | 0.6005 |
| **Δ** | | **−4 слоя** | **+0.0055** | **+0.021** | −0.0115 |

**Вывод:** Устранение неявной обрезки 32 соседей позволило сократить глубину с 12 до 8 слоёв при **улучшении** ROC (+0.0055) и PR (+0.021). Это подтверждает гипотезу, что прежняя глубина компенсировала разреженность графа, а не необходимость в большем receptive field.

**Про F1.** F1 у v2 (0.6005) ниже, чем у v1 (0.612) — из-за сдвига калибровки: `mean prob` у v2 = 0.294, у v1 ≈ 0.31. Оптимальный порог смещается с 0.272 до 0.247, что даёт более агрессивный recall (0.80 vs 0.744) при меньшем precision (0.48 vs 0.519). Это не деградация модели, а разница калибровки; ROC и PR — основные метрики.

### 📈 WBCE (Weighted BCE): sweep по α на 500 train

**Идея.** Вес точки = `1 + α · exp(−y/τ) · y`. Точки в **глубине интерфейса** (малое y) получают больший вес → модель учится быть увереннее в центре.

**Параметры:** 500 train / 50 val, 8L, τ=4.0 Å, seed=42, test=412.

| α | val ROC | val PR | test ROC | test PR | ΔAUC(quantile) |
|:---|:---|:---|:---|:---|:---|
| **0** (baseline) | 0.7549 | 0.4975 | 0.7709 | 0.5065 | — |
| 0.25 | 0.7714 | 0.4967 | **0.7871** | 0.5174 | +0.0011 |
| **0.5** | **0.7749** | **0.5155** | 0.7841 | **0.5237** | **+0.0038** |
| 0.75 | 0.7549 | 0.4947 | 0.7785 | 0.5123 | +0.0013 |
| 1.0 | 0.7672 | 0.4863 | 0.7844 | 0.5047 | −0.0028 |

**Bootstrap (paired, 412 белков, 1000 итераций):**
- ΔAUC(quantile) для α=0.5: **+0.0038**
- 95% CI: **[+0.0023, +0.0053]**
- p-value: **< 0.0001**

**Вывод.** WBCE α=0.5 **реально улучшает ранжирование** интерфейсных точек — не только сдвигает калибровку. Другие α (0.25, 0.75, 1.0) не проходят тест `per-protein quantile` — их улучшение объясняется сдвигом.

### Что делает WBCE: структура предсказания

`check_threshold_dynamics` (50 белков, 500 train):

| thr | baseline IoU_core | WBCE α=0.5 | WBCE α=1.0 |
|:---|:---|:---|:---|
| 0.40 | 0.211 | 0.221 | 0.200 |
| 0.50 | 0.183 | **0.229** | 0.221 |
| 0.60 | 0.140 | 0.223 | **0.230** |
| **0.70** | **0.000** | 0.151 | **0.226** |

**largest component (доля точек в крупнейшей компоненте):**

| thr | baseline | WBCE α=0.5 | WBCE α=1.0 |
|:---|:---|:---|:---|
| 0.50 | 0.762 | 0.852 | 0.859 |
| 0.60 | 0.688 | 0.809 | 0.819 |
| **0.70** | **0.017** | 0.722 | **0.824** |

При высоком пороге baseline **обнуляется** (IoU = 0), WBCE **сжимается связно к ядру** интерфейса. Это делает WBCE перспективным для **zero-shot переноса** на разметку dMaSIF (узкая SASA-разметка → нужен высокий порог).

## 🔮 Будущие эксперименты

### WBCE(depth) — zero-shot generalization на чужую разметку

**Проблема.** WBCE требует знания `y` (расстояние до партнёра). Для dMaSIF-разметки есть только бинарный `iface`. Нужен топологический аналог `y`, не зависящий от партнёра.

**Идея.** Заменить `y` на **топологическую глубину** — геодезическое расстояние по локальным рёбрам (0–2 Å) до ближайшей **фоновой** точки. Это мера «погруженности» точки в интерфейс.

**Реализация.** `compute_geodesic_depth.py` — мультиисточниковый BFS от фоновых точек через виртуальный узел.

**Статистика** (посчитано на 5462 файлах):
```
depth_max:           mean=8.61  max=25
depth_median_iface:  mean=3.04
```

**Формула для веса:**
```
w = 1 + α · (1 − exp(−depth / τ_d)) · iface
```
где `τ_d` — аналог `τ`, в хопах. Оптимум, вероятно, `τ_d ≈ 2.0`.

**План проверки:**
1. WBCE(depth) α=0.5, τ_d=2.0 на 500 файлах → сравнить с WBCE(y) α=0.5 (ROC 0.784, PR 0.524).
   - Если **ROC ≥ 0.78** → depth работает как замена `y`, идём в dMaSIF.
   - Если **ROC < 0.76** → depth слабее, zero-shot не выйдет.
2. Если (1) успешен — обучение на dMaSIF train с WBCE(depth), оценка на dMaSIF test через `evaluate_on_dmasif.py`.
3. Sweep по порогу для zero-shot.

**Команда:**
```bash
CUDA_VISIBLE_DEVICES=0,1 python -u train_clean_ddp.py \
    --data_dir ./processed/graphs_multiscale_new_depth \
    --log_dir ./logs/wbce_depth_a05 \
    --n_files 500 --n_val 50 \
    --layers 8 --hidden 32 --heads 4 \
    --hard_ratio 2.0 --bias_init -0.85 \
    --weight_alpha 0.5 --weight_tau 2.0 \
    --weight_mode depth \
    --epochs 30 --val_interval 2
```

### Zero-shot на dMaSIF

После выбора финальной модели (α=0.5 на 5000) — **sweep по порогу** на dMaSIF test.

**Идея.** Наша разметка (SES–SES 4 Å) шире, чем dMaSIF (ΔSASA). Но **ядро пересекается**. При росте порога наше пятно сжимается связно к ядру (мы это показали через `check_threshold_dynamics`) → ROC на dMaSIF-разметке может **сохраняться** в широком диапазоне порогов.

**Гипотеза:** WBCE-обученная модель сохраняет ROC на dMaSIF при высоком пороге, baseline — обнуляется.

### Homology-aware split

Текущий сплит — **случайный**, что даёт оптимистичную оценку. Для честного сравнения с dMaSIF/DeepPPIPS нужен homology-aware split (CD-HIT или MMseqs2, порог 30–40% identity). Направление будущей работы.

## ⚠️ Ограничения и важные нюансы

1. **Разбиение по гомологии.** Все внешние бенчмарки (dMaSIF/MaSIF, DeepPPIPS) используют homology-aware split. Наш — **случайный**. Прямое сравнение метрик некорректно. Нужен CD-HIT/MMseqs2 для честного сравнения.

2. **Test ≠ clean held-out.** `evaluate.py` подбирает порог по test (бисекция на F1). Threshold-free метрики (ROC/PR) — честные; F1 — оптимистичен.

3. **Обрезка 32 соседей.** В v1-графах неявно работала через `radius_graph`. Снятие дало +0.005 ROC, +0.021 PR и позволило сократить глубину с 12 до 8 слоёв.

4. **Smoothness регуляризация** (λ > 0) на GNN избыточна — 8 слоёв уже обеспечивают согласованность.

5. **WBCE α=1.0** — только сдвиг калибровки без улучшения ранжирования (ΔAUC(quantile) = −0.0028). Оптимум — **α=0.5**.

6. **Разное определение интерфейса.** Наше (SES–SES 4 Å) vs dMaSIF (ΔSASA). Прямое сравнение absolute numbers некорректно. Для cross-modality reference — используем.

7. **`shuffle(42)` чувствителен к длине списка.** Потеря даже одного файла меняет всю перестановку. Всегда проверять через `compare_shuffles.py`.
